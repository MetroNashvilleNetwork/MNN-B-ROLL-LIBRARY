# MNN B-Roll Library

A local, offline **"stock-footage site" for your own b-roll** — browse a grid of
video thumbnails, hover to preview, search and filter, then jump straight to the
file for your project. Footage lives on a Microsoft SharePoint drive that is
**mapped as a Windows network drive** (e.g. `X:\2026 ... B-Roll Footage`); the
app treats it as a plain local folder — no SharePoint API or Microsoft Graph.

The UI runs as a small local web app that opens in your browser. It is 100%
offline — nothing leaves the machine; the "web" part is just localhost.

This is a standalone tool. Footage filenames and descriptive metadata are
produced by a separate clipper program; this search engine simply indexes the
resulting files on the mapped drive.

### The gallery (default UI)

`python main.py` (or **`Run B-Roll Search.bat`**) starts a local server and
opens your browser to a footage gallery:

* a **search bar** (keyword search over filename / folder / shooter),
* a **thumbnail grid**; hover a card to **play a short preview**,
* **filters** in the sidebar — shooter, shot type, file type, month range,
* click a clip for a **detail view** (bigger preview + all metadata) with
  **Open file location** (reveals it in Windows Explorer) and **Copy file path**,
* a **Re-index** button, and infinite scroll.

Thumbnails and previews are generated by ffmpeg and cached locally in `cache\`,
so each clip is only processed once. Without ffmpeg the gallery still works —
cards show a labelled placeholder and previews are skipped.

### Command-line usage

```powershell
python main.py                    # launch the web gallery (default, localhost)
python main.py --share            # also share on the local network (manager demo)
python main.py --desktop          # launch the simple PyQt5 desktop UI instead
python main.py --validate         # check the mapped drive is reachable
python main.py --index            # scan + update the index (incremental)
python main.py --index --full     # force re-read every file
python main.py --stats            # file count, last run, shooters/types
python main.py --search "blodgett oven"   # quick text search in the terminal
python main.py --port 9000 --no-browser   # web gallery on a custom port
```

### How footage is interpreted

The indexer understands the archive layout
`<root-year>\<shooter>\<month>\<filename>`:

* **shooter** = the top-level folder (Aaron, Gil, …),
* **month** = the month subfolder (gives a month-level "shoot date"; the year
  comes from the root folder name, e.g. `2026 …`),
* **shot type** = auto-detected from the filename (Closeup, Wide, Medium,
  Static, Aerial, Tracking, Handheld, Pan, Tilt, Zoom, …),
* hyphenated filename words become search keywords,
* `desktop.ini` and hidden/system files are skipped.

Date filtering uses the folder-derived month range; exact filesystem
created/modified timestamps are also stored and shown.

## Requirements

- **Windows 10/11** (Dell machines) — the SharePoint folder must already be
  mapped/synced to a drive letter or UNC path in File Explorer.
- **Python 3.8+**
- **PyQt5** (Phase 3 UI) — `pip install -r requirements.txt`
- **ffprobe** (Phase 2 video metadata) — bundled `ffprobe.exe` or on PATH.
  Not required for Phase 1.

No internet connection is required at runtime once SharePoint is mapped.

## Quick start (non-technical staff)

1. Double-click **`Setup (first time).bat`** once per computer (installs requirements).
2. Double-click **`Run B-Roll Search.bat`** to open the gallery in your browser.

That's it. The mapped drive path is already set in `config.json`.

### Showing someone else (e.g. your manager)

Double-click **`Share on Network (show manager).bat`**. It prints a link like
`http://10.x.x.x:8765/` — send that to anyone on the same MNN network and they
can browse the library from their own computer. Keep the window open while they
view; close it to stop sharing. (Equivalent CLI: `python main.py --share`.)

## Quick start (developer / manual)

```powershell
# 1. Install dependencies
python -m pip install -r requirements.txt

# 2. Create your config (copies the example on first run)
python main.py --init-config

# 3. Edit config.json and set your mapped drive path(s), e.g. "X:/2026 ... B-Roll Footage"

# 4. Check that the drive is reachable
python main.py --validate

# 5. Build the index, then launch the search UI
python main.py --index
python main.py
```

### Optional: video durations / resolution

Drop an `ffprobe.exe` into the **`tools\`** folder (see `tools\README.txt`) and
re-index. The app auto-detects it — no PATH changes needed. Everything works
without it; you just won't see durations.

## Configuration

Settings live in `config.json` (create it from `config.example.json` or run
`python main.py --init-config`). Key fields:

| Field | Meaning |
|-------|---------|
| `footage_paths` | One or more mapped-drive paths to scan. Use forward slashes (`Z:/B-Roll`) **or** escaped backslashes (`Z:\\B-Roll`). |
| `database_path` | Where the local SQLite index is stored. |
| `video_extensions` | File types treated as footage (MP4, MXF, MOV, …). |
| `auto_index` | Daily auto-index behavior (run on launch / interval). |
| `ffprobe_path` | Path to `ffprobe.exe`, or just `ffprobe` if on PATH. |
| `extract_video_metadata` | Whether to read duration/resolution/codec via ffprobe. |

See `config.example.json` for a fully documented template.
